# Plan 15-01: API Testing Backend

## Objective

Add `runType` field to the `Run` Prisma model, implement a spec parser for OpenAPI/Swagger JSON/YAML, an HTTP-based `apiAgent` that executes requests per spec and validates responses, and wire it into `agentJob.ts` so a run with `runType:'api'` routes to the API agent instead of the browser agent.

### Task 4: Implement specParser

**File:** `src/agent/specParser.ts`

```typescript
export interface ParsedEndpoint {
  method: string;        // GET, POST, PUT, DELETE, PATCH
  path: string;          // e.g. /api/v1/users/{id}
  operationId?: string;
  summary?: string;
  requestBodySchema?: unknown;  // JSON schema
  expectedStatuses: number[];   // e.g. [200, 201, 400]
  parameters: Array<{
    name: string;
    in: 'query' | 'path' | 'header' | 'body';
    required: boolean;
    schema?: unknown;
  }>;
}

export function parseOpenApiSpec(specJson: string): ParsedEndpoint[]
```

- Support OpenAPI 3.x (`openapi: '3.x.x'`) and Swagger 2.x (`swagger: '2.0'`)
- Parse `paths` object — iterate methods per path
- For each operation: extract `operationId`, `summary`, `parameters`, `requestBody` (OA3) or `parameters[in=body]` (Swagger 2)
- Collect `responses` keys as expected status codes (filter numeric)
- Use `JSON.parse` — no external YAML library needed (accept JSON only in MVP)
- Throw `InvalidSpecError` with helpful message on malformed input

### Task 5: Implement apiAgent

**File:** `src/agent/apiAgent.ts`

```typescript
export interface ApiTestResult {
  endpoint: string;       // "GET /api/v1/users"
  operationId?: string;
  status: number;
  responseTime: number;   // ms
  passed: boolean;
  failureReason?: string;
  requestBody?: unknown;
  responseBody?: unknown;
  expectedStatuses: number[];
}

export interface ApiAgentOptions {
  baseUrl: string;
  endpoints: ParsedEndpoint[];
  maxEndpoints?: number;  // default 50
}

export class ApiAgent {
  async run(options: ApiAgentOptions): Promise<ApiTestResult[]>
}
```

Implementation:
- Loop through `endpoints` (up to `maxEndpoints`)
- For each endpoint: expand path params with placeholder values (use `"test-id"` for string params, `1` for numeric)
- Fill query params if required
- Construct request body from schema if present (use minimal valid object with placeholder values)
- Execute HTTP request using native `fetch` with 10s timeout
- Record: status code, response time, whether status is in `expectedStatuses`
- Capture first 500 chars of response body for analysis
- Handle fetch errors (network timeout, connection refused) as `passed: false`
- Log each test with `logger.info`

### Task 8: Wire apiAgent into agentJob processor

**File:** `src/worker/agentJob.ts`

After fetching the run record, branch on `runType`:
```typescript
if (job.data.runType === 'api') {
  return await processApiJob(job, run);
}
// existing browser agent code
```

Add `processApiJob(job, run)`:
1. Parse spec with `parseOpenApiSpec(job.data.apiSpec)`
2. Run `ApiAgent.run({ baseUrl: run.url, endpoints })`
3. Save API test results as `observations` (eventType: `'api_test_result'`, payload: each `ApiTestResult`)
4. Update run status to `complete`
5. Call `analyzeApiTestResults` and save report (reportType: `'api_test_report'`)
6. Log completion
